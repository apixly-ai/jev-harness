# 开放目标、动态工具与 Jev 托管

[English](open-goals.md) · [任务协议](agent-contract.zh-CN.md) · [案例](use-cases.zh-CN.md)

**给目标，AI 写任务脚本，Jev 根据新观察选择下一步，直到取得可核验结果或明确停止。**

任务的路线、将遇到的页面、资源和参数可以在启动时未知。有界指工具权限、允许的
作用范围和资源预算；不要求预写完整步骤或枚举所有未来候选。每次实际调用仍只使用
注册工具与程序在当前现场提供的参数。

## 核心功能怎么呈现

| 环节 | 负责方 | 用户应看到的结果 |
| --- | --- | --- |
| 定义任务 | 主 AI | 目标、工具签名与描述、观测和完成检查、执行范围与预算 |
| 发现现场 | 程序 | 当步才出现的页面、文件、资源、证据与参数候选 |
| 决定下一步 | Jev | 选择工具，按描述和依赖绑定参数，选择继续、复核或停止 |
| 执行与反馈 | 程序 | 实际操作结果、刷新后的现场、准入的结果摘要和历史 |
| 交付 | 独立检查与主 AI | 可回查出处或目标状态的产物，以及未解决项 |

脚本应封装能力，不应包含替 Jev 选下一步的任务专用路由器。确定的计算、解析和
验证可以在代码中完成。工具前置条件可以控制当前可用能力；需要探索的未知事实不宜
被声明为启动时必须已存在的 `required_context`。

当前 `Parameter.choices(ctx, observation, bound_arguments)` 已能按新现场生成候选，
`depends_on` 支持选定父参数后再获取子候选。无需另设静态完整参数池。

## 旗舰：未知路径的多页资料探索

**目标示例：**“从这个陌生目录入口开始，找出三个满足给定约束的自托管工具，
保存带可核对来源的比较结果。”

AI 写脚本并提供通用能力：打开当前发现的来源、读取页面、选择当前筛选项、提取
证据、保存出处包。Jev 决定先看哪个来源、何时筛选、哪个分支值得继续，以及现有
证据是否足够提交给独立检查。进入页面后才会发现新链接和筛选依赖。

第一版交付结构化出处包：工具名、来源 URL、原文片段、约束匹配情况和采集引用。自由搜索词或
最终长文需要显式的可信生成工具或主 AI；本项目当前的 Jev 选择接口不生成任意文本。
生成工具的结果经程序校验后才能成为下一轮数据候选，其模型用量和耗时单独记录。

### 验收如何证明自主探索

1. 冻结同一脚本与通用工具，只改变入口和任务要求。
2. 使用两条不同成功路线和一条缺来源的变体；启动时脚本看不到隐藏路由或答案。
3. 打开页面后才提供新的目标引用；每轮候选来自现场，不能由 fixture 答案表产生。
4. 记录 Jev 输入、工具及参数候选描述、原始选择、实际轨迹和独立核验结果。
5. 独立核对三个不同工具及每项约束的来源支持，再核对保存的 URL 与原文；
   缺少支持时保留未解决状态，DOM 中出现“done”不构成完成证明。
6. 保留错分支、复核、阻塞、未知用量和完整耗时；不自动重试不确定操作。

**状态：设计与验收要求，尚无本案例的真实 Jev/Camofox 完成证据。**
历史固定表单验收仍可在[证据账本](../reports/README.zh-CN.md)核查，不能替代本案例。

## 两个复用同一机制的扩展案例

### 仓库探索与问题定位

给一个仓库和已有失败记录，例如任务重复提交。主 AI 提供受控文件列表、读取、
符号搜索、查看已有测试/日志产物和保存证据包等工具。Jev 根据新调用关系和结果
选择文件、符号及证据。假设或解释的生成
可由显式生成工具辅助，不能把生成文本直接用作 shell 命令。

独立检查核对引用文件、版本与报告中的依据。首个案例只读源码与已有产物，
把诊断保存在源码树之外，不执行仓库程序。**状态：设计，尚未进行完整真实验收。**

### 受控 API 的任务诊断

给失败任务的入口 ID 和诊断目标。通用工具列出资源、读取状态/日志、发现依赖、
分页取证、选择已允许的检查并保存诊断。资源 ID 和依赖在响应后才出现，Jev 决定
检查顺序和参数。首轮使用只读合成环境，避免将诊断演示变成生产修复。

独立检查重新查询目标与来源，区分已证实原因、待复核假设和不可取得的证据。
**状态：设计，尚未进行完整真实验收。**

## 当前应优先补齐的机制

| 优先项 | 当前情况 | 下一次验收要证明什么 |
| --- | --- | --- |
| 通用浏览发现 | 已有动态 surface 目标；默认适配器仍有表单顺序偏向，未覆盖全部浏览动作 | 不同未知分支、同名链接、筛选依赖和长正文；执行仍遵守来源与 freshness |
| 证据引用与有界读取 | 原文在私有结果/日志；默认近期完整摘要可能在 15k 字符预算处停止 | 大结果用来源、摘要和引用进入上下文；旧证据可按片段读取，无需丢弃目标和约束 |
| 执行前探索恢复 | 空依赖参数域目前终止为 needs_context；作者可用 available 表达前置条件 | 明确可恢复的缺失交回 Jev 选择发现工具，限制决策次数；不重试已开始的不确定操作 |

这些是当前缺口和开发顺序，不是已发布能力。适配器和案例验证通用机制，业务特例
不进入核心。跨进程恢复和原生桌面完成也仍未证明。

## 主页应该展示什么

第一屏展示用户目标、AI 产出的脚本契约，以及 Jev 取得的动态现场。主案例展示新
候选出现、不同路线、证据积累、完成或缺证据停止。设计演示、scripted 离线结果、
真实模型运行和历史截图回放分别标记。

接入入口指向 [spec 与任务协议](agent-contract.zh-CN.md)，验收入口指向
[原始证据](../reports/README.zh-CN.md)。不以修复数量或测试数量代替开放任务完成，
不在尚未进行主 AI 直调对照前声称整任务降费或提速。
